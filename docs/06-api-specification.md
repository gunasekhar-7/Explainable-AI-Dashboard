# API Specification — Aletheia v1

Base path: `/api/v1` · Content type: `application/json` (uploads: `multipart/form-data`) · Auth: bearer JWT or
`X-API-Key` · OpenAPI: generated by FastAPI at `/api/v1/openapi.json`, interactive docs at `/docs`
(protected in production).

---

## 1. Conventions

### 1.1 Response envelope

Successful single resources return the resource object directly. Collections return an envelope:

```json
{
  "items": [ { "id": "...", "name": "churn-logreg" } ],
  "meta": { "limit": 25, "next_cursor": "eyJjIjoiMjAyNi0xMS0wM1QxMDoxMjozM1oiLCJpIjo0Mn0", "total_estimate": 12 }
}
```

### 1.2 Errors (RFC 9457 `application/problem+json`)

```json
{
  "type": "https://aletheia.dev/errors/model-schema-mismatch",
  "title": "Model schema mismatch",
  "status": 409,
  "code": "MODEL_SCHEMA_MISMATCH",
  "detail": "Model requires 46 transformed features; dataset version provides 44.",
  "request_id": "01J8Z7K2V3",
  "errors": [
    { "field": "InternetService", "issue": "missing_required_feature" },
    { "field": "TotalCharges", "issue": "dtype_mismatch", "expected": "numeric", "actual": "string" }
  ]
}
```

`code` is stable and is what clients branch on; `detail` and `errors` are for humans. The catalogue is in §7.

### 1.3 Pagination

Keyset pagination on `(created_at, id)`: `?limit=25&cursor=...`. `limit` default 25, max 200. Keyset, not
offset, because prediction and audit tables are append-heavy and offsets get slower and less stable.

### 1.4 Idempotency

`Idempotency-Key` is accepted on job-creating and batch endpoints and stored as `jobs.idempotency_key`
(unique). Replaying the same key returns the existing job with `200` instead of creating a new one.

### 1.5 Rate limits

Per identity (user or API key). Response headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`,
`X-RateLimit-Reset`; exceeding returns `429` with `Retry-After`.

| Endpoint class | viewer | analyst | admin |
|---|---|---|---|
| Reads | 120/min | 300/min | 600/min |
| Prediction (single) | 30/min | 120/min | 240/min |
| Compute (explanations, fairness, drift, reports) | — (403) | 30/min | 60/min |
| Registration / activation / deletion | — (403) | — (403) | 60/min |
| `POST /auth/token` | 5 failures / 15 min per (email, source address), `429` + `Retry-After` | same | same |

`GET /health*` is unauthenticated and unlimited. Login is limited per account **and** per source address, so
neither credential stuffing against one account nor spraying across many is unlimited; failures are counted
after a constant-time hash comparison, audited as `auth.login_failed`, and never log the attempted password.
Delay after the third failure is exponential (0.5 s, 1 s, 2 s, …) before the limit trips.

### 1.6 Time, units and naming

All timestamps are ISO 8601 UTC with `Z`. Probabilities are `0..1` floats; SHAP values are in the model's
output space and the response always states which (`output_space: "log_odds" | "probability" | "margin"`).
Field names are `snake_case`. Every analysis response includes `caveats: string[]`.

### 6.4.1 Ground-truth labels (late-arriving outcomes)

Every label-based feature — outcome calibration, the performance half of a drift report, re-assessing
fairness once outcomes are known — needs truth for rows that were already scored. This is the interface
for it; without it those features have no input.

| Method | Path | Role | Purpose |
|---|---|---|---|
| POST | `/model-versions/{version_id}/labels` | analyst | Attach outcomes to already-scored predictions |
| GET | `/model-versions/{version_id}/labels/coverage?dataset_version_id=` | viewer | Labelled / unlabelled counts per label source |

```http
POST /api/v1/model-versions/{id}/labels
{ "labels": [
    { "prediction_id": "c7a1f0e2-…", "ground_truth": 1, "observed_at": "2026-11-20T00:00:00Z", "label_source": "crm_export" },
    { "subject_ref": "7590-VHVEG", "ground_truth": 0, "observed_at": "2026-11-20T00:00:00Z" } ] }

200 OK
{ "accepted": 2, "duplicate_identical": 0, "unmatched": 0,
  "coverage": { "labelled": 1412, "total": 7043, "fraction": 0.2005 } }
```

Rules: one label per prediction (`UNIQUE (prediction_id)`); replaying an identical label is idempotent
(`409` only when the value differs); an unmatched `subject_ref` is counted and reported, never attached to a
neighbouring row; acceptance is per row, so one bad row does not discard the batch; unlabelled predictions
are excluded from label-based metrics and shown as excluded, never assumed negative.

Errors: `422 LABELS_INVALID`, `409 LABEL_CONFLICT`, `422 PREDICTION_NOT_FOUND` (per row).

## 7. Error catalogue

| Code | HTTP | Meaning |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Request body/params failed Pydantic validation |
| `UNAUTHENTICATED` | 401 | Missing or invalid credentials |
| `FORBIDDEN` | 403 | Authenticated but insufficient role |
| `NOT_FOUND` | 404 | Resource does not exist |
| `CONFLICT` | 409 | Uniqueness or state conflict (e.g. duplicate version) |
| `RATE_LIMITED` | 429 | Identity exceeded its budget |
| `DATASET_INVALID` | 422 | Dataset could not be parsed/validated |
| `TARGET_NOT_BINARY` | 422 | Declared target is not binary |
| `ARTIFACT_SOURCE_NOT_ALLOWED` | 403 | Artifact source outside the trust policy |
| `ARTIFACT_INTEGRITY_FAILED` | 422 | SHA-256 mismatch or manifest disagreement |
| `ARTIFACT_UNLOADABLE` | 422 | Sandbox load failed/timed out |
| `UNSUPPORTED_ARTIFACT` | 422 | No adapter accepted the object |
| `MODEL_SCHEMA_MISMATCH` | 409 | Model incompatible with dataset version |
| `PREDICTION_INPUT_INVALID` | 422 | Per-field input problems |
| `EXPLANATION_FIDELITY_ERROR` | 500 | Additivity/fidelity check failed; result withheld |
| `EXPLAINER_UNAVAILABLE` | 422 | No explainer for this model type/params |
| `FAIRNESS_ATTRIBUTE_UNAVAILABLE` | 422 | Declared group attribute not present |
| `FAIRNESS_LABELS_UNAVAILABLE` | 422 | Ground truth missing for the dataset version |
| `FAIRNESS_DECLARATION_REQUIRED` | 422 | Missing privileged group / favourable label |
| `INSUFFICIENT_SAMPLES` | 422 | No group meets minimum support |
| `INSUFFICIENT_DATA` | 422 | Drift needs more rows/bin coverage |
| `JOB_FAILED` | 409 | Referenced job ended in failure |
| `JOB_CANCELLED` | 409 | Referenced job was cancelled |
| `STORAGE_UNAVAILABLE` | 503 | Artifact store unreachable |
| `LABELS_INVALID` | 422 | Label payload malformed, or a value outside the target domain |
| `LABEL_CONFLICT` | 409 | A different label already exists for this prediction |
| `LABEL_COVERAGE_INSUFFICIENT` | 422 | A label-based metric was requested with fewer labelled rows than its stated minimum |
| `INTERNAL_ERROR` | 500 | Unhandled; always carries `request_id` |

An unexpected exception never leaks a traceback or a database message to the client; it is logged with the
`request_id` and returned as `INTERNAL_ERROR`.

## 8. Contract tests (Stage 9 gate)

1. Every endpoint in this document exists and returns the documented status codes for success, unauthorised,
   forbidden, not-found and invalid-input cases.
2. The error response for every 4xx/5xx validates against the problem schema (required `code`, `request_id`).
3. OpenAPI output is committed as a snapshot; a change requires an explicit diff review.
4. Pagination: a cursor returned for page *n* yields page *n+1* without duplicates or gaps under concurrent
   inserts (verified with a fixture that inserts between pages).
5. Idempotent replay of a job-creating request returns the same `job_id` and creates exactly one row.
